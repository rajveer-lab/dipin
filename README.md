# Dip In

A live-match companion for cricket fans who can't watch every ball. It tells you whether the match is worth watching right now, pings you only when it gets tense, and catches you up on what you missed when you come back.

## What it does

- **Should I watch?** A tension meter from 0 to 100, built from how close the result is, how late it is in the match and how recently a wicket fell. The top of the screen shifts from cool blue to hot red with it.
- **Pings that are worth it.** Alerts for tense finishes, big wickets and last overs, nothing else. A lock-screen view shows what a fan sees while they're away.
- **Catch me up.** A summary of everything since you last looked, innings break included.
- **Ask.** Questions about the match ("Can CSK still win?", "Who bowls the last over?"), answered from the live scorecard.

Two matches are included: a made-up demo match with a one-run finish, and the IPL 2019 Final (MI v CSK) replayed ball by ball from Cricsheet data.

## Run it

Needs Node.js. There are no packages to install.

```bash
node serve.js
```

Then open http://localhost:5317.

```bash
node build.js
```

This writes `dist/index.html`, one self-contained file for any static host, and `dist/dipin.html`, the same page without the document skeleton.

## How it works

| File | What it does |
|---|---|
| `engine.js` | The match engine. Takes a feed of balls and works out the score, win chances, tension and alerts after each one. Also simulates the demo match through the same feed. |
| `adapters/cricsheet.js` | Turns a Cricsheet match file into that feed. |
| `data/replays.js` | The bundled replays, generated by `tools/make-replays.js` from `data/cricsheet/`. |
| `ai.js` | Talks to a language model for Catch me up and Ask. |
| `app.js`, `index.html`, `styles.css` | The app itself. |

The engine has no idea whether a ball is simulated, replayed or live. A live source only needs to send balls in the format described at the top of `engine.js`.

### Win model

The win chances come from a model fitted on 1,195 IPL matches from 2008 to 2026:

1. It estimates the runs still to come from balls and wickets left, using the same idea as DLS, scaled to the season's typical first-innings score.
2. It turns that into a win chance, tuned against how real chases actually finished.

On seasons it never saw (2024 to 2026) it cut the error in chase predictions (log loss) from 1.01 to 0.37. Over all 1,195 matches, it pings fans in 87% of close finishes and only 7% of one-sided ones.

`LEVEL` in `engine.js` is the average first-innings score for the current season (196 in 2026). Update it each season.

### AI

Catch me up and Ask use a language model when one is reachable:

- the `sample` capability, when the page runs as a claude.ai artifact;
- otherwise a `POST api/ai` route on the same host. That route is not part of this repo yet.

Without either, a built-in narrator answers from the same match facts, so every feature still works offline.

## Checks

```bash
node tools/check-engine.js
node tools/check-replay.js
```

- `check-engine` replays the demo match against a recorded baseline and confirms that a ball-by-ball feed rebuilds the same match.
- `check-replay` compares the replayed final with Cricsheet's own figures for every batter, bowler and ball.

## Tools

These need the IPL archive from Cricsheet (`ipl_json.zip` on [cricsheet.org/downloads](https://cricsheet.org/downloads/)), unzipped into a folder:

```bash
node tools/calibrate.js <folder> [--final]
node tools/alert-stats.js <folder>
```

- `calibrate` refits the win model and tests it on held-out seasons.
- `alert-stats` measures how well the pings separate close finishes from one-sided games.

## Data

Ball-by-ball data comes from [Cricsheet](https://cricsheet.org) under the [Open Data Commons Attribution License](https://opendatacommons.org/licenses/by/1-0/). `data/cricsheet/1181768.json` is the original Cricsheet file, unchanged. The teams in the demo match are made up.
